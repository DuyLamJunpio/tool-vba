## DEC-107 — Windows Excel licensing gate, hidden sheets and client hardening (29/10/2026, owner-decided)

Context: the owner explicitly fixed the workbook-close and device-code decisions and approved proposals C1–C7/C9 for `tool-vba/license-sample/api-v1-one-file`. Earlier work already implemented DEC-104 renewal, `ogh = 0`, removal of account-JWT paths and definitive cache rejection recovery. Those behaviours remain; this decision replaces the contradictory open-workbook and server-issued sheet-password rules in architecture §7. No server entitlement policy or endpoint contract changes.

Decision:

1. When access cannot be granted, show guidance and close only the workbook containing the licensing module, `ThisWorkbook.Close SaveChanges:=False`, after OK/X. Keep Excel and all other workbooks open. Excel never receives or stores an account JWT; use device-code, redeem and validate-device only. Account login and code approval stay on Store. Embed public keys only, never private keys/shared secrets; all verification failures deny access.
2. Preserve definitive cache recovery: clear on local fingerprint mismatch or invalid cached signature/kid/product/version, and on HTTP 4xx except 429 with `TOKEN_INVALID`, `DEVICE_REVOKED` or `DEVICE_MISMATCH`. Only successful clearing permits a new device-code offer in that same startup, at most once; No/X closes. Keep credentials on network/rate-limit/timestamp/5xx errors and on expired/suspended licenses so renewal or unblocking can validate them again. Preserve DEC-104: passing only `exp` does not invalidate ownership of the renewal credential; no offline access past exp. Preserve signed `rvi`/`ogh`, including online validation on open for `ogh = 0`.
3. C1: `Cfg_ProtectedSheetNames` defaults empty. The author provides a separate visible enable-macros guide and merges close/save handlers into ThisWorkbook. Ship configured premium sheets `xlSheetVeryHidden`; show them only with entitlement and hide them on refusal, close and before save. After saving, restore the view only if still entitled. No sheet password is requested or returned by the server. Hidden sheets are a deterrent, not encryption; disabled or modified macros remain a limitation.
4. C2: DPAPI cache also holds the greatest UTC timestamp seen, which only increases; token `iat` after signature verification is a floor. An earlier local time denies access with `CLOCK_ROLLBACK` and guidance to synchronize Windows time and reopen. Keep the cache; updating the maximum never changes the successful-validation anchor or extends rvi/ogh. Deleting/restoring the entire cache can bypass this local history.
5. C3: when a guarded feature checks access after validation is due during the session, attempt validate-device once per rvi cycle, with a reentry flag and existing timeouts. Success is transparent; only network failure can use still-valid offline grace. No background timer. Losing entitlement hides the sheets and invokes the guidance/close gate.
6. C4–C7: use fixed public product-specific DPAPI entropy in protect/unprotect. An old undecryptable cache is treated as absent without a decryption error and may need activation once. Set TLS 1.2/1.3 before opening WinHTTP requests, keep certificate validation and redirect blocking. Use Windows user proxy/PAC configuration and WinHTTP defaults, with optional `Cfg_ProxyServer` empty by default and no credentials. Read the volume serial from `%SystemDrive%`; C: keeps the old hash inputs, other system drives may change an activated machine's fingerprint and require reactivation/removal of the old device if seats are full.
7. C9: support two kid/public-key pairs. Keep the sample's current public key with `k2026-10` first and leave the second pair empty until rotation. Select by header kid, bind payload kid to it and reject unknown IDs or a signature from the wrong key. Duplicate/partial/invalid pairs deny configuration. Do not weaken `VerifyEd25519Detached`.

Consequences / validation: the source remains ASCII with unaccented Vietnamese messages; API URL, product key, version and activation-page URL stay empty until an approved release is configured. No token/fingerprint/device_code is written to sheets, logs, URLs or dialogs. The sample has 64 mock cases, 57 signed regression cases generated with the API signer and ephemeral test keys, and 44 manual cases. HTTP/cache/UI/sheet regression effects are stubbed; DPAPI test ciphertext stays in memory. The new VBA still needs Debug > Compile VBAProject and both suites on Excel Windows, followed by workbook/Store/API/proxy smoke tests before release. Static contract/hash and .NET tests cannot substitute for that. No commit or deployment is authorized by this decision.
